# CHRYSPHARMACY v2.2 — SMS.to, προσωπικά μηνύματα, σύγχρονο dashboard

Η έκδοση αυτή αποτελεί αναβάθμιση της **CHRYSPHARMACY v2/v2.1** με **την ίδια δομή PostgreSQL** και τα ίδια endpoints για πελάτες/συνταγές.

## Τι διορθώθηκε

1. **SMS ανά συνταγή:** Στη σελίδα `/admin/clients/<id>/prescriptions`, το κουμπί «Αποστολή SMS» εξηγεί όλους τους λόγους που είναι ανενεργό: λείπει API key, SMS_ENABLED, συναίνεση, κινητό, η ημερομηνία δεν έχει φτάσει, η συνταγή είναι ανενεργή ή υπάρχει ήδη καταχώριση αποστολής. Το μήνυμα δεν περιέχει ΑΜΚΑ ούτε φαρμακευτική πληροφορία.
2. **Dashboard:** Εμφανίζει πλήρη λίστα των ενεργών συνταγών με `opens_on = σήμερα`, και ξεχωριστές ενότητες για παλαιότερες ενεργές και μελλοντικές. Η ημερομηνία «σήμερα» υπολογίζεται στη ζώνη ώρας **Europe/Athens**, όχι με βάση τη ζώνη ώρας του server.
3. **Προσωπικά μηνύματα:** Πλαϊνό μενού **Προσωπικά μηνύματα** → `/admin/messages`, επιλογή πελάτη και σύνταξη μηνύματος → `/admin/clients/<id>/messages`. Εμφανίζεται στο `/client` μετά από σύνδεση του πελάτη. **Δεν είναι SMS ή email**, απλώς αποθηκεύεται στη βάση και εμφανίζεται στην προσωπική καρτέλα.
4. **Λογαριασμοί παλιών πελατών:** Σε **Πελάτες → Επεξεργασία**, συμπληρώνεις username και αρχικό password για πελάτη που δεν έχει λογαριασμό, ώστε να συνδεθεί στο portal. Για υπάρχον λογαριασμό το username προβάλλεται, ενώ το password αφήνεται κενό εκτός αν επιθυμείς αλλαγή.
5. **Εμφάνιση:** Πλαϊνό μενού, πιο έντονο μωβ, πετρόλ, χρυσό και κοραλί, νέα cards, ιστορικό επικοινωνίας, responsive mobile CSS. Το **Bootstrap 5.3.6 είναι αποθηκευμένο τοπικά** στο `static/vendor`, επομένως η βασική μορφοποίηση δεν απαιτεί πρόσβαση στο internet/CDN.

## Αναβάθμιση ΑΠΟ v2.1 με διατήρηση της ίδιας βάσης

**ΜΗΝ αντικαταστήσεις την παλιά εγκατάσταση προτού επιβεβαιώσεις ότι η νέα λειτουργεί.** ΜΗΝ τρέξεις SQL μεταφοράς δεδομένων ή `init-db` στην ήδη λειτουργική βάση: δεν απαιτούνται αλλαγές σε πίνακες ή στήλες από v2.1 σε v2.2.

### 1) Αντίγραφο ασφαλείας της PostgreSQL

Σταμάτησε τον Flask server της παλιάς έκδοσης με `Ctrl+C`. Χρησιμοποίησε το όνομα βάσης και τον PostgreSQL χρήστη που έχεις ήδη στο `.env`:

```bash
mkdir -p ~/pharmacy_backups
pg_dump -h 127.0.0.1 -U chrys_user_v2 -d chryspharmacy_v2 -Fc -f ~/pharmacy_backups/chryspharmacy_before_v22.dump
ls -lh ~/pharmacy_backups/chryspharmacy_before_v22.dump
```

Αν τα ονόματα είναι διαφορετικά, άλλαξέ τα. Βεβαιώσου ότι το backup ολοκληρώθηκε χωρίς σφάλμα και φυλάσσεται σε προστατευμένο χώρο. Μην ανεβάζεις backup που περιέχει πελάτες σε δημόσια υπηρεσία.

### 2) Τοποθέτηση αρχείων σε ξεχωριστό φάκελο

Αποσυμπίεσε το ZIP ώστε να υπάρχει ο φάκελος:

```
/home/takis/Documents/farmakeio/chryspharmacy_v2_2/
```

Από τερματικό:

```bash
cd ~/Documents/farmakeio/chryspharmacy_v2_2
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### 3) Διατήρηση της ίδιας PostgreSQL και των SMS.to κλειδιών

Αντέγραψε το **δικό σου** `.env` από την προηγούμενη έκδοση (προσαρμόζεις τη διαδρομή αν έχει άλλο όνομα):

```bash
cp ~/Documents/farmakeio/chryspharmacy_v2_1/.env .env
chmod 600 .env
nano .env
```

Επιβεβαίωσε:

```dotenv
SECRET_KEY=ΤΟ_ΥΠΑΡΧΟΝ_ΙΣΧΥΡΟ_SECRET_KEY
DATABASE_URL=postgresql+psycopg2://chrys_user_v2:Ο_ΥΠΑΡΧΩΝ_ΚΩΔΙΚΟΣ@127.0.0.1:5432/chryspharmacy_v2
SMS_ENABLED=true
SMS_TO_API_KEY=ΤΟ_ΔΙΚΟ_ΣΟΥ_ΚΛΕΙΔΙ
SMS_SENDER_ID=CHRYSPHARM
EMAIL_ENABLED=false
COOKIE_SECURE=false
```

Τα στοιχεία `SECRET_KEY`, `DATABASE_URL`, `SMS_TO_API_KEY` πρέπει να είναι ακριβώς τα δικά σου. **Μην τα στείλεις σε συνομιλία ή screenshot**. Αν ο κωδικός της DB έχει σύμβολα URL, χρειάζεται percent-encoding στο DATABASE_URL. `COOKIE_SECURE=false` επιτρέπεται μόνο σε προσωρινή τοπική εγκατάσταση με HTTP· σε παραγωγική εγκατάσταση HTTPS πρέπει να είναι `true`.

### 4) Εκκίνηση

```bash
cd ~/Documents/farmakeio/chryspharmacy_v2_2
source .venv/bin/activate
python -m flask --app app:create_app run --host 0.0.0.0 --port 5001
```

Άνοιξε `http://192.168.1.30:5001` **μόνο από έμπιστο τοπικό δίκτυο**. Η πραγματική διεύθυνση Raspberry Pi μπορεί να διαφέρει.

**Προσοχή στο παλιό cron:** Αν έχεις προγραμματίσει `send-due` στην προηγούμενη έκδοση, ΜΗΝ προσθέσεις δεύτερο cron στην ίδια βάση/εγκατάσταση. Διόρθωσε τη διαδρομή της υπάρχουσας cron εργασίας όταν ολοκληρώσεις την αναβάθμιση.

## Έλεγχος σημερινών συνταγών

1. Μπες στον διαχειριστή `/admin` και έλεγξε την ημερομηνία που αναγράφεται στο dashboard.
2. Η λίστα **«Συνταγές που ανοίγουν σήμερα»** δείχνει όλες τις ενεργές συνταγές όπου `opens_on` ισούται με τη συγκεκριμένη ημερομηνία. Η ημερομηνία SMS **δεν αλλάζει** αυτή τη λίστα.
3. Αν μια καταχώριση δεν εμφανίζεται, έλεγξε στην καρτέλα πελάτη ότι **Ενεργή** είναι επιλεγμένο και `Ημερομηνία ανοίγματος` είναι ακριβώς η σημερινή (π.χ. `2026-10-09`). Οι παλαιότερες καταχωρίσεις εμφανίζονται στην ενότητα «Παλαιότερες ενεργές» και οι επόμενες στις «Επόμενες ημερομηνίες».
4. Μην πατήσεις «Έλεγχος και αποστολή σημερινών» πριν δοκιμάσεις με **δικό σου κινητό**. Το κουμπί μπορεί να προκαλέσει πραγματικές και χρεώσιμες αποστολές.

## Γιατί το SMS είναι γκρι;

Άνοιξε `Πελάτες → Συνταγές / SMS`. Ακριβώς κάτω από τη συγκεκριμένη συνταγή υπάρχει πλαίσιο **«Γιατί δεν είναι διαθέσιμη η αποστολή»**.

Επιτρέπεται αποστολή εφόσον ισχύουν **όλα**:

- `.env`: `SMS_ENABLED=true` και έγκυρο `SMS_TO_API_KEY` (απαιτείται επανεκκίνηση μετά την αλλαγή `.env`).
- Πελάτης: αριθμός ελληνικού κινητού `69xxxxxxxx` ή `+3069xxxxxxxx` και ενεργή συναίνεση SMS στην καρτέλα.
- Συνταγή: **Ενεργή**, ημερομηνία `opens_on` σήμερα ή παλαιότερη.
- Δεν υπάρχει **προηγούμενη προσπάθεια SMS** για την ίδια συνταγή. Αυτό είναι σκόπιμο ώστε να μην γίνει κατά λάθος χρεώσιμη επαναποστολή σε περίπτωση αβέβαιου σφάλματος δικτύου. Σε περίπτωση αποτυχίας, έλεγξε τον λογαριασμό SMS.to και το ιστορικό πριν επιχειρήσεις οποιαδήποτε περαιτέρω ενέργεια.

Για δοκιμή, δημιούργησε **δοκιμαστικό πελάτη με το δικό σου κινητό**, συγκατάθεση και νέα συνταγή με σημερινή ημερομηνία. Στο SMS.to χρειάζεται εγκεκριμένο Sender ID και διαθέσιμο υπόλοιπο. API: `POST https://api.sms.to/sms/send`, με `Authorization: Bearer ...`, payload `to`, `message`, `sender_id`. Αποδοχή `success:true` και `message_id` σημαίνει **σε ουρά**, όχι ότι παραδόθηκε στο τηλέφωνο. Δεν έχει υλοποιηθεί webhook παράδοσης.

## Προσωπικά μηνύματα και είσοδος πελάτη

1. Στον διαχειριστή πάτα **Προσωπικά μηνύματα** (πλαϊνό μενού), επίλεξε πελάτη, γράψε μήνυμα και αποθήκευσέ το.
2. Εναλλακτικά: **Πελάτες → Μηνύματα καρτέλας**, ή από τις συνταγές του πελάτη **Μήνυμα στην καρτέλα**.
3. Το μήνυμα εμφανίζεται στο **Ιστορικό μηνυμάτων** του διαχειριστή και στον πελάτη στη διεύθυνση `/client`, μετά τη σύνδεσή του.
4. Αν ο πελάτης δεν έχει λογαριασμό: **Πελάτες → Επεξεργασία → Username πελάτη / Αρχικός κωδικός → Αποθήκευση**. Για υπάρχον λογαριασμό μην βάλεις κωδικό εκτός αν τον αλλάζεις.
5. Η είσοδος πελάτη είναι `/login/client`, του διαχειριστή `/login/admin`.

Τα προσωπικά μηνύματα **ΔΕΝ** αποστέλλονται με SMS.to και **ΔΕΝ** στέλνουν push/email. Είναι καταχωρίσεις που εμφανίζονται **μόνο** στο portal του συνδεδεμένου πελάτη.

## Τι ΔΕΝ αλλάζει στη βάση

Η έκδοση αυτή χρησιμοποιεί τους υπάρχοντες πίνακες `users`, `clients` (με `amka`), `prescriptions`, `messages`, `notification_logs`. Δεν προσθέτει στήλες ή πίνακες σε σχέση με την v2.1. **Δεν χρειάζεται SQL migration** για την αναβάθμιση αυτή αν η προηγούμενη v2.1 δουλεύει ήδη. Αν η παλιά βάση έχει διαφορετική δομή, **μην** τρέξεις μη επιβεβαιωμένα ALTER/DROP SQL.

## Προστασία δεδομένων

Η εφαρμογή αποτελεί λειτουργική βάση ανάπτυξης, όχι έτοιμη λύση για πραγματικά ιατρικά δεδομένα στο internet. Απαιτούνται HTTPS, προστασία πρόσβασης, ασφαλής διατήρηση αρχείων/backup, ενημερώσεις ασφαλείας και έλεγχος συμμόρφωσης πριν από παραγωγική χρήση. Το ΑΜΚΑ δεν αποστέλλεται σε SMS ή email. Μην εκθέτεις τον Flask development server δημόσια.
